System design

Three views of the local, single-user repository investigator. The diagrams show implemented components and boundaries, one live question, and the persisted conversation model.

01 / Architecture

Local app and external services

The browser calls a localhost Next.js API. The server pins GitHub reads to a commit, asks Groq for bounded decisions and a structured answer, validates citations, and saves the run in SQLite.

02 / Sequence

One live question

Every question resolves the current default commit. The planner may request up to eight validated reads. The final answer is accepted only when its citation IDs match evidence from the pinned commit.

03 / Data model

Conversation history in SQLite

A repository owns conversations. Each run is tied to one SHA and owns its messages, trace, inspected paths, evidence excerpts, and citations. Reused evidence is copied into the new run so deletion of its original conversation does not break citations.

Source of truth: investigation loop, Groq planner, GitHub adapter, and history schema. These diagrams document the local MVP; they do not imply a deployed or multi-user service.
